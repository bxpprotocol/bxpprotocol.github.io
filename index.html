Protocol

One pipeline. Every exposure source.

A phone sensor, a fixed IoT node, and a reference-grade monitor all produce the same BXP record. Five stages, fully specified, byte-for-byte identical across implementations.

01

Locate

Coordinates resolved to a geohash cell with a documented precision floor.

02

Detect

Source tiered — phone, community, or reference instrument — and classified as native, imported, community, research, or simulated.

03

Interpret

Units normalised, quality control applied, corrections recorded separately from raw values.

04

Protect

Privacy enforced: hashed identifiers, coarsened location, k-anonymity for aggregates.

05

Report

Stored, queryable, and replicable across nodes with an identical response schema.

Binary representation

.bxp
// 32-byte header, CRC32, optional gzip
0x00  magic        BXP\0
0x04  version      2.0
0x06  fileType     READING
0x08  flags        COMPRESSED | DRAFT
0x0C  timestamp    µs since epoch
0x10  payloadLen   4096
0x14  headerCRC32  ✓ verified
0x18  payloadCRC32 ✓ verified
0x1C  payload      gzip(JSON)

Experimental BXP-HRI is a composite 0–100 index weighted by WHO disability-adjusted life-year burden data. It is not clinically or epidemiologically validated and must not be used for medical decisions. Methodology is published in full so it can be reviewed and challenged.

Why BXP

The barrier was never hardware.

Developers

Implement BXP without talking to us.

The specification, the golden vectors, and both reference SDKs are public. If your implementation passes the conformance suite, it is BXP 2.0 compliant — that is the whole test.

# pip install bxp-sdk
from bxp_sdk import write_bxp, read_bxp, calculate_risk, BXPClient

# composite risk from raw sensor values
risk = calculate_risk(pm25=67.0, no2=31.0, duration="24h", population="sensitive")
print(risk["score"], risk["level"])   # 89.6 VERY_HIGH

# write, verify, submit
write_bxp("accra.bxp.json", {"latitude": 5.6037, "longitude": -0.1870, "pm25": 47.2, "source": "native"})
print(read_bxp("accra.bxp.json")["_integrityOk"])              # True

BXPClient("http://localhost:5000").submit(latitude=5.6037, longitude=-0.1870, pm25=47.2)
// npm install @bxp/sdk

1

Conformance-first, not trust-based

Any implementation that passes the 17 golden vectors is compliant. No certification authority required.

2

Versioned wire format

MAJOR changes get 18 months advance notice and dual-version support. MINOR additions are ignored-and-preserved by design.

3

Embeddable

A 32-byte fixed header and a flat JSON payload keep the codec viable on microcontrollers, not just servers.

4

Honest about limits

Unspecified areas are marked unspecified. Unimplemented features raise rather than silently no-op.

Trust

Open by construction, not by promise.

Governance, security posture, and known limitations are written down in the repository — including the parts that are not finished yet.

◈ Apache 2.0 license

No royalties, no restrictions, no gatekeepers. Anyone can use, modify, or redistribute. Read the license.

◉ Published governance

Who decides specification changes, through what process, and what is aspirational versus real. Read GOVERNANCE.md.

◐ Documented security posture

Attack surfaces, disclosure timeline, secure deployment checklist, and a full list of known limitations stated as limitations. Read SECURITY.md.

◑ Archived and citable

Spec and reference implementation each carry a permanent Zenodo DOI, so published research can cite a fixed version. Spec DOI · Implementation DOI.

◇ Privacy by specification

SHA-256 hashed identifiers, geohash precision floors, k-anonymity for aggregates, and cryptographic deletion — enforced in the reference implementation, not promised in a policy document.

⬡ Federated, not centralised

Pull-based replication with cursor pagination and deletion tombstones. No node owns the network, and no operator has to trust a single point of failure.
